# v0.8 lane C — LOD streaming by default on desktop (design note)

The owner's item 8 (docs/wip/v08-plan.md): his new big city scan, Opole Cathedral (SuperSplat `ba7aa29d`,
format `ssog` = streamed SOG with levels of detail, ~1.2 GB, 60.3 M splats in 10 levels), opened on a
computer does not show the level-of-detail (LOD) technology; on a computer it must be on by default;
SuperSplat will probably make LOD its default soon, so nothing may break when it does.

## What is known (investigation, 2026-10-16)

- **What SuperSplat serves for ba7aa29d.** CDN folder `v1/`: `settings.json` 200, `lod-meta.json` 200
  (generator "splat-transform v3.8.0 via shramko-sog-lod-converter v1.2.0", `lodLevels` 10, `counts`
  30.2 M .. 59 k), `meta.json` 403, `scene.compressed.ply` 403, `scene.voxel.json` 403 (no walls). The
  explore API lists it as `format: "ssog"`, size 1 198 557 625 bytes, and now also `lodCounts` (the same
  10 numbers) and `shBands` 3.
- **SuperSplat is moving to LOD.** The 48 newest public uploads (2026-10-16): 25 `ssog` (18 of them with
  2..6 levels, 7 with one), 23 `sog`; every item now carries `lodCounts`. So more and more scenes will
  stream in levels, and a scene may well carry both `lod-meta.json` and `meta.json` one day.
- **What superspl.at does with it.** The page `superspl.at/s?id=ba7aa29d` bootstraps the viewer
  (@playcanvas/supersplat-viewer 1.37.0) with `contentUrl = .../v1/lod-meta.json`. The viewer clamps the
  LOD range to the coarsest level for the reveal, then opens `lodRange 0..1000`; splat budget 4 M on
  desktop, 2 M on a phone (1 M / 2 M in its performance mode), budget mode "target", lodBehindPenalty 5,
  lodUpdateAngle 90, unified rendering, no frame-rate governor (it renders on demand). Measured in the
  in-app browser on this PC: 2.87 M splats drawn, levels 0, 1, 2, 3, 4, 5 and 9 fetched.
- **What our app does (release 0df437d), measured** (`probe-v08-lod.ts`, local release, visible system
  Chrome 1280x800, WebGPU, 30 Hz display; `evidence/2026-10-16/v08-lod-probe-before*.json`):
  `resolveScene` already picks `lod-meta.json`; the renderer streams it with the viewer's engine settings
  (coarse reveal at 0.9-1.6 s, then 0..1000, 4 M "target"). But the quality governor lowered the drawing
  right after the reveal: 4 M / scale 1.0 -> 3 M / 0.85 -> 2.5 M / 0.7 -> 2 M / 0.6 within 2.5 s, and it
  climbed back one step per 5 s: full quality only 17 s after the reveal, with the camera standing still.
  The per-frame trace shows why: the misses were the streamer's own hitches (the reveal requested 154
  files at once: frames of 124, 67, 42 ms; then 34-41 ms frames while 116 -> 76 files arrived), not a GPU
  that cannot draw 4 M (frames held for the GPU: 1 in that time). While flying through a city the streamer
  never stops, so the governor keeps the scan coarse and at a lower resolution: on the owner's PC (4K
  monitor at 30 Hz, other programs on the same GPU) that is exactly "no level of detail".
- The in-app browser pane was hidden while it measured (rAF throttled): its reading (1.5 M, scale 0.5)
  is not evidence; every number here comes from a visible window.
- **The deeper cause, found while fixing it** (probe runs after-2/after-3 with the governor's own numbers):
  the governor learned the display period as the 5th percentile of intervals measured with
  `performance.now()` when the frame's code ran, and judged frames from the very first interval. Right
  after the reveal that period read 9-16 ms on a 30 Hz screen (a 5.5 ms "catch-up" interval follows a
  120 ms callback), so every on-time 33 ms frame counted as missed and the drawing stepped down. With the
  frame's rAF timestamp (the display's own frame time) and 60 intervals learned before any frame is
  judged, the period reads 33.0-33.2 ms from the first judged frame.

## What was built

1. **Content order with fallbacks** (`packages/scenes/src/content.ts`, `resolveScene`). One table
   (`CONTENT_FILES`) names the files a scene folder can hold, best first: `lod-meta.json` (streamed,
   levels of detail), `meta.json` (one SOG). `resolveScene` returns `content`: every file the CDN did not
   deny, in that order, when at least one is confirmed (`contentUrl`/`contentKind` = the first, so every
   caller works as before). A `lod-meta.json` lookup that did not answer is still tried first (the old
   rule silently opened `meta.json` and the scan lost its levels). A new file name SuperSplat introduces
   is one more row. The API's `format` is never needed to open a scene: a renamed or listed format reads
   as `""` = unknown and the CDN decides (API test `test_a_renamed_or_listed_format_reads_as_unknown`).
2. **The session opens the first file that works** (`apps/fly/src/session/index.ts` `loadContent`). The
   renderer reads `lod-meta.json` before the engine does and refuses one the engine cannot open
   (`packages/render-pc/src/lod.ts` `lodMetaProblem`: the engine reads `lodLevels`/`filenames`/`tree` in
   its constructor inside its own HTTP callback; review R2 measured that the engine then fails the asset
   itself with an English "Error loading gsplat octree" (its Http wraps the callback in a try/catch), so
   the check's worth is telling a damaged file apart, as `BrokenFileError` -> scene error 'broken', before
   any engine asset exists, not a page that would wait forever). The session unloads the attempt and opens the next file;
   `session.contentFailures` says what failed and why; `scene.contentUrl` names the file on screen.
   Nothing left: a file whose lookup never answered makes it a network error, else the first file's error.
3. **The governor stops starving the levels of detail** (`packages/render-pc/src/governor.ts`,
   `apps/fly/src/app/quality.ts`):
   - its clock is the frame's rAF timestamp (`renderer.frameTime`), not `performance.now()`;
   - it judges no frame before `PERIOD_MIN_SAMPLES` (60) intervals, and its first step needs a whole
     window of judged frames;
   - (review R1: removed) an excuse for late or held frames while the scan streams, counted only above
     a third of the window. It made 0-1 difference on the still camera and hid an overload of up to
     ~43 % dropped frames for the whole of a flight. Every missed frame counts again; the ones that came
     while the scan streamed (`renderer.streamTicks`) are only counted apart (`streamHitches`, report).
4. **Phones as SuperSplat's viewer** (`packages/render-pc/src/drawing.ts`): levels of detail stream on
   every device; the top splat budget is 4 M on a desktop (`DEFAULT_BUDGET_M`), 2 M where the viewer
   says mobile (`MOBILE_BUDGET_M`, the viewer's `budgets.mobile.high`; `isViewerMobile`: Android, iPhone,
   iPad, iPod in the user agent, PlayCanvas `platform.mobile`; review R5: an iPadOS Safari that says
   "Macintosh" gets 4 M as on superspl.at, and is still refused stochastic by `isHandheld`); a link's
   budget on a phone is refused with the existing note. `accept-v07-render.ts` R3 now expects 2 M on a phone.
5. **Seeing it**: F3 shows a second line, e.g. "Levels of detail: 10, chosen by distance - 3.9 of 4.0 M
   splats - 100 % resolution" (+ "lowered from 4.0 M to hold the frame rate" when the governor lowered it,
   + "the streamed file did not open, the single file is shown" after a fallback); four languages
   (`packages/i18n/locales/fly/lod/`). `window.__gsfpv.lod()` and a bug report's technical details carry
   the same report (`apps/fly/src/app/lod.ts`).

## Decisions for docs/decisions.md (the lead numbers them at merge)

- **Levels of detail first, with fallbacks.** A scene folder's content files are tried in one order
  (`CONTENT_FILES`: lod-meta.json, meta.json); an unconfirmed lod-meta.json is still tried first; a
  broken one falls back to meta.json. Why: SuperSplat is moving uploads to streamed SOG and a folder may
  hold both; a dropped lookup must not cost a scan its levels, a broken file must not hang the page.
- **The quality governor runs on the display's clock and learns before it judges.** rAF timestamps,
  60 intervals learned, a whole window before the first step; every missed frame counts, streaming or not
  (review R1). Why: measured on ba7aa29d, the old clock taught a 9-16 ms period on a 30 Hz screen, which
  kept a 60 M-splat city coarse and at 60 % resolution (D33 still holds: missed frames, not frame time).
- **Draw under SuperSplat's viewer's budgets**: 2 M where it says mobile (Android, iPhone, iPad, iPod in
  the user agent), else 4 M (viewer 1.35-1.37 budgets; review R5).

  `tools/bench/src/probe-v08-lod.ts` (per-level splats from the engine's octree instances, files and
  bytes per level, the governor's step/period/hitches per second, a per-frame trace) and the acceptance
  `tools/bench/src/accept-v08-lod.ts` (`SITE=` the new local release, `SITE_BEFORE=` an older one as the
  control). Both draw: GPU lock.
- Traps met: a hidden browser pane throttles rAF and makes the governor drop everything (measure only in
  a visible window); `performance.now()` frame intervals have catch-up frames that fool a percentile;
  the engine fails a lod-meta.json it cannot parse with its own English error (review R2 corrected the
  earlier "never fails"), so check it first to say 'broken' in the pilot's language; the engine's octree internals live at `app.renderer.gsplatDirector.camerasMap -> layersMap ->
  gsplatManager.world._octreeInstances` (benches only, never product code).
- Not verified here: the owner's own PC (4K monitor at 30 Hz, DaVinci and other programs on the same
  GPU) and flying through the city (the measurements keep the camera still); a real phone or tablet
  (only a phone user agent in desktop Chrome).
