# v0.7 lane C — ideas UI: admin kanban + landing roadmap (design note)

Owner's item 3 (docs/wip/v07-plan.md): every idea in the admin with a kanban of its implementation, in
sync with the landing, which shows what is done and what is planned. Lane B builds the store and the
APIs in parallel; this lane codes against the contracts below and tests against a mock of them.

## Contracts this lane assumes (lane B to confirm; the lead reconciles at merge)

Public roadmap — as in the plan, plus two optional fields the seed carries and the landing uses:
`GET /api/roadmap` -> `{"v":1,"items":[{"id","kind":"feature|idea|bug","status":"planned|in_progress|done",
"title":{"en",...},"text"?,"fromPilot":bool,"done"?:ISO,"release"?:sha,"group"?:string,"order"?:number}]}`.
`group` = the landing's group id (`radio controls drone crash camera scenes walls settings`); without it a
done item goes into a trailing "More" group, unless the snapshot already placed it (the seed's grouping
survives an API that does not echo `group`). `order` sorts within a column. nginx needs
`location = /api/roadmap` (GET only, no cookies) — whichever lane adds it.

Seed (written here, loaded once by B into an empty store): `apps/api/locales/roadmap-seed.json`
`{"v":1,"items":[{"id":"F-<slug>","kind":"feature","status":"done|in_progress|accepted","title":{en,es,pl,ru},"order":n,"group":"<id>"}]}`.

Admin ideas API (assumed; all under `/api/admin/`, session cookie, `X-CSRF` on POST, `{ok:false,reason}` on errors):

| Call | Body | Answer |
|---|---|---|
| `GET ideas` | | `{ok, ideas: Idea[]}` |
| `POST ideas/status` | `{id, status}` | `{ok, idea}` |
| `POST ideas/urgency` | `{id, urgency}` | `{ok, idea}` |
| `POST ideas/comment` | `{id, text}` | `{ok, idea}` |
| `POST ideas/public` | `{id, title: {en,es,pl,ru}, roadmap: bool, group: string or null}` | `{ok, idea}` |
| `POST ideas/reply` | `{id, text}` (the server quotes the pilot's words and sends from the owner's Gmail) | `{ok, idea}`; 409 `no-contact` |
| `POST ideas/thanks/draft` | `{id}` (nothing is sent) | `{ok, to, lang, subject, body}` |
| `POST ideas/thanks/send` | `{id, subject, body}` | `{ok, idea}` |
| `GET reports/<id>/diagnostics` | (exists today) | the stored JSON |

`Idea = {id, kind: idea|bug|note|feature, status: new|accepted|in_progress|done|rejected, urgency:
low|normal|high|urgent, ts, text, fromPilot, locale?, page?, scene?, release?, contact?, suspect?,
diagnostics?: bool|"skipped", comments?: [{ts, text, via?}], public?: {title, roadmap, group?},
order?, done?, mails?: [{ts, kind: reply|thanks, to, ok}]}`. A record with an unknown status is not
guessed into a column: the tab says how many it could not show.

The relayed request of 2026-10-13 ("all user data in the chat too") is lane B's Telegram side; on this
side the card shows everything the pilot sent (the contact itself, language, page, scene, release,
diagnostics), not only whether a contact was left.

## Kanban rules

- Columns New / Accepted (the work queue) / In progress / Done / Rejected. Queue order: urgency, then
  `order`, then age; New and Rejected newest first; Done by done date, newest first.
- Move: drag a card onto a column; or focus a card's handle and press Left/Right; or the card's
  Column select (touch). A move to the same column sends nothing.
- Moving a pilot's idea with an e-mail contact to Done opens a draft thank-you (`thanks/draft`);
  it is sent only by its Send button. Reply by e-mail: a form on the card, sent only by its button.
- Roadmap visibility needs an English public title; missing languages are named on the card (the
  landing shows English there).
