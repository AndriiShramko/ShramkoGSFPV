## Design note

### 1. What the research says (full text and links: `docs/research/drone-models.md`)

- Nine presets, four families: **open-prop X** (Nazgul Evoque F5 V3 freestyle, Mach R5 Sport racer), **ducted 2" HD
  cinewhoop** (Pavo20 Pro, Pavo20 Pro II 3S and 4S, Pavo Pico 1.8"), **tiny whoop** (Meteor65 Pro, Air65: 65 mm,
  analog, 1S), **coaxial X8 cinelifter** (Taurus X8).
- The cinelifter question. iFlight sells the Taurus X8 V3 O4 **without a camera**: the page says it is built for "DSLR
  or cinema cameras", names Red Komodo, Zcam and BMPCC, lists maximum payload 3 kg, XT60H cables to the RED Komodo, Z CAM
  E2 and BMPCC 4K/6K as accessories, and states that the camera in its photos "is for display only". The weights (1989 g,
  2872 g with the pack) exclude it; the hover time (5.5 min) is for a **2 kg** load. The preset's mass (4872 g) is that
  2 kg load, and its id says Komodo: **the preset assumes a cinema camera**, so the model carries one by default.
- The 5-inch Evoque F5 V3 sells a GoPro 9/10/11 TPU mount as an accessory; the weights (492 g / 736 g) exclude a
  GoPro, so none is drawn. Its DJI O4 Air Unit Pro is itself a 4K camera. No other preset's mass includes an action camera.

### 2. Code layout (`apps/fly/src/drones3d/`, one lazy chunk, nothing imported by the main flight path)

- `equipment.ts` (data, no engine): per preset id the family and the parts the preset does not hold (motor stator size,
  blades, FPV system, action camera, battery connector, camera tilt), each with `basis: 'maker' | 'typical'` and a
  `ref`. Numbers the preset already holds (wheelbase, prop diameter, cells, mAh, KV, masses) are read from the preset,
  never copied; a test pins that.
- `shapes.ts` (pure): parametric geometry as typed arrays (lathe, rounded box, tube, ring, prop blade, torus...), no
  engine; unit-tested (indices valid, normals unit length, closed volumes, bounds).
- `models.ts` (pure): per family a parametric builder that turns a build into a part list (geometry + material id +
  transform + callout anchor). Sizes come from the build: the model's motor-to-motor diagonal equals the preset's
  wheelbase, the prop disc its prop diameter (tests).
- `materials.ts`: PBR material table (carbon fibre with a procedural twill weave, anodised aluminium, rubber, PA12 /
  TPU plastic, lens glass, PCB, LiPo wrap, copper) -> `pc.StandardMaterial`.
- `studio.ts`: own `AppBase` with a graphics device of its own (WebGPU, WebGL2 fallback), a soft studio (procedural
  softbox environment, key light with a soft shadow, rim light, a matte floor that takes the shadow), turntable +
  drag-to-orbit + wheel/pinch zoom. Drawn only while its host element is connected and visible; `dispose()` destroys
  the app and the device and counts what is freed.
- `callouts.ts`: HTML labels with leader lines that follow the model's anchors; text from `locales/fly/drones3d/*`
  (en/es/pl/ru), brand and model names are not translated.
- `index.ts`: the entry the picker loads with `import()`; `viewer.ts` the controller the picker and the pause card use.

### 3. Where it shows

- Drone picker: a stage on top (the drone in use at first; clicking a card or its "3D" button shows that drone) with
  the turntable, callouts and the key specs; cards below as today. One viewer, rebuilt per preset, one device.
- Pause menu: a "Your drone" row (`PauseMenu.addRow`): a small turntable, name, class, four numbers, "Change drone".
  Created when the menu opens, gone with it (the viewer disposes itself when its host leaves the page).
- If no device can be created the stage keeps the equipment list and says the 3D view is unavailable.

### 4. Cinelifter payload (default = the preset, A6 unchanged)

Choice: RED Komodo 6K rig (the preset's 2000 g), Blackmagic Pocket Cinema Camera 6K Pro rig, GoPro HERO13 Black, none.
Masses are the makers' body masses plus the same lens/media/plate allowance the preset already holds (see the research
note); thrust is held constant, so the mass change moves the thrust-to-weight, hover throttle and inertia together.
`ParamOverrides.payloadG` (absent = the preset, bit for bit); a drone-scope setting `physics.payload`; the model shows
the chosen camera. Negative controls: the base params ignore it; the default value equals the preset's numbers exactly.

### 5. Checks

- Node unit tests (vitest): equipment table covers `DRONE_IDS`; shapes valid; per-family model sizes vs the preset;
  every callout key exists in 4 languages; payload physics (TWR, hover, inertia monotone) with controls.
- Browser (`tools/bench/src/accept-v09-drones3d.ts`, GPU lock held while drawing): for every preset the picker's stage
  draws a non-empty model (pixel count of the canvas vs an empty clear; different presets give different pictures),
  callouts visible, orbit by drag changes the picture, closing frees GPU memory (device and resource counters from the
  viewer's own tally and `GPUDevice.lost`/destroy), pause card draws and goes. Negative control: the base release has no
  model (no stage, no canvas). Screenshots: `evidence/2026-10-18/drones/*.png`.
