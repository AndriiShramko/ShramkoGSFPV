# v0.12 plan: Fly by Sound, stage 1

Architect's plan, 2026-11-07, written on v03-lead ac0fae5 (all `file:line` below are on that commit). Source of truth: ShramkoSonicFPV `docs/design/stage-1-spec.md` (17e772c). Shared types: ShramkoSonicFPV `src/contract.ts` (0476e77). Lanes never push, deploy or SSH; the lead merges, moves the submodule and releases.

## 1. Decisions

- **Repository link: git submodule.** ShramkoSonicFPV at `packages/sonic-fpv` (URL `https://github.com/AndriiShramko/ShramkoSonicFPV.git`), consumed as workspace package `@shramko/sonic-fpv` (`pnpm-workspace.yaml` already globs `packages/*`), CI checkout with `submodules: true`. GitHub shows the folder as a link to the pinned commit; the gitlink pins it in every release (`scripts/build-release.mjs:137` takes the superproject sha). Gates checked: typecheck (`pnpm -r typecheck` runs its own script); vitest (root `vitest.config.ts:5` globs `packages/*/test/**`, so its Node tests run here too: browser proofs must live outside `test/`); architecture walks `packages/` (rule 7 added in step 0); B18 unaffected (`tools/bench/src/accept-repo.ts:31-35` scans `git ls-files`, which lists the gitlink, not the files, and exempts any `locales/` path); licences: MIT, no runtime deps. Rejected: npm package (a publish per change, `minimumReleaseAgeExclude` churn), pnpm git dependency (lanes cannot push, so no sha to point at), subtree copy (no visible link). Costs, handled in step 0 and lane rules: worktrees do not init submodules; a local path clone needs `-c protocol.file.allow=always`; only the lead moves the gitlink; the repo must be public on GitHub before `main` carries the gitlink.
- **Lesson worlds run without a scan** through a built-in world option of the session (2.5). Collider = the analytic SDF seen as voxels (`AnalyticWorld.solidAt`), named by `AnalyticWorld.digest`, so logs replay.
- **Assists are inputs, for every source** (keyboard, gamepad, radio): a pre-gate hook in `Controls` runs a lesson pilot (velocity loop, altitude hold, numeric caps, auto-arm). sim-core is untouched; the A6 hash stays.
- **Soft bump = `crash.enabled` off** for the mode (prefs session layer); touches come from sim `contact` events.
- **Checkpoint reset = move `session.spawn`, then `respawnStart()`**: a logged 'manual-start' respawn, exact in replays. Y (rewind) stays as it is.
- **Package replay = the 30 Hz pose track** driving camera and engine; the simulator's input log rides along as optional `sim-log.json` for exact re-simulation.
- **Listener frame = heading** (yaw only, tilt ignored): Web Audio's default listener axes (contract header).
- **Pilot sound prefs and lesson progress = a new prefs collection `sonic`** (`packages/prefs/src/doc.ts:29-33`), not settings, so no catalogue rows. Key bindings do go through the catalogue (step 0).
- **Entry** `/{lang}/fly/?sonic=start|<lessonId>`; site landing `/{lang}/sound/`. **Keys** (all free today): T record, U send, I status, Z repeat last line, G glossary; in the mode R short = last checkpoint, R long = lesson start, N = next step, digits = answers, [ ] locked.

Per frame: `ctx.events` 'frame' at the end of `Flight.frame()` (`apps/fly/src/app/flight.ts:126-136`), every runner event as 'sim' (`flight.ts:240`). **2.2 Audio today.** `app/builtin/sound.ts` owns one AudioContext, made at the first pointerdown or keydown, or at once after an earlier activation (80-100); radio and gamepad input is no activation. `MotorSound` wires its master to `ac.destination` (`audio/motor-sound.ts:170-173`) and is silent unless armed, flying, unpaused, visible and `sound.motors` (74-75; default on at 15 %, `packages/prefs/src/defs/sound.ts`). **2.3 Assists and input.** Not today: radio and gamepad frames go `onFrame -> controls.raw` (`app/input.ts:198-199`, `controls.ts:317-323`) straight to the arm gate (`controls.ts:370-381`); the easy and game pilots serve keyboard and touch only (`input.ts:72-82`, `controls.ts:204-208`); a profile with a mode switch overrides the mode (`controls.ts:286-289`, `384-387`); arming needs centred sticks, throttle under 5 % and a rising edge (`packages/input/src/calib.ts:1914-1941`). Installed for every source while a lesson runs, null otherwise.

**2.4 Collision, rays, contact.** `VoxelCollision.queryRay(o, d, maxDist)` (`packages/collision/src/vendor/voxel-collision.ts:383`) returns the hit point only; normal from `querySurfaceNormal` (318); no material. `session.collision` is the flown grid (`session/index.ts:923-932`): `transformCollision` reuses the octree with cell size s*res (`collision/src/transform.ts` header), so a ray crosses distance/(s*res) cells, one octree descent each (`isVoxelSolid`, 844). Winter Garden (`apps/fly/public/showcase.json`: voxelCm 3.2) at x5 has 16 cm cells: about 200 descents per 20 m ray, about 6000 for 30 rays (INFERRED). Cast per frame (up to 60 Hz) on the main thread, never per 1 ms tick; budget 1 ms p95, measured in v12-flight step 3. Analytic collider: the `collision/src/synthetic.ts:9-21` pattern (a `VoxelCollision` whose `isVoxelSolid` asks a function), exported as `analyticCollision(min, max, voxelM, solid)` with primitives culled by a coarse grid, wrapped in `VoxelContactWorld` (`collision/src/world.ts:64`) for sim-core's `ContactWorld` (`sim.ts:37-47`). Contact (`sim.ts:736-891`): at or above vCrash with crashes on, a crash, the crash view (`app/builtin/crash.ts:84`) and an automatic respawn or next scene (`director.ts:211-221`); with `crash.enabled` off (read at `app/builtin/respawn.ts:50-52`, `67`) the same hit is a bounce and a 'contact' event carrying speed only (no point, no normal). Debounce: one touch per 0.5 s of quiet.

## 6. Where the code contradicts the spec (keep the spec's intent; the spec should say this)

1. Section 2, "the drone's own frame": the listener uses the heading frame (tilt ignored) by default; the body frame is a pilot option (`SonicPrefs.listenerFrame`).
2. Section 6, "strings live in this repository's locales/": lesson, cue, survey and spoken strings only; the simulator's own chrome for the mode (menus, key labels, GPU hint, admin, site) lives in `packages/i18n/locales/**`, the only place its catalogue and parity tests read.
3. Section 7: add an optional `sim-log.json` (the simulator's input log, `app/logs.ts:19` format) for exact re-simulation; replay itself plays the 30 Hz track, because `LivesPlayer` cannot play poses.
4. Section 8, mail "up to about 20 MB": 8 MB in stage 1 unless the API container gets more memory (64 MB, `deploy/compose.yml:51`); bigger packages go as an admin link.
5. Section 5, "the existing rewind is reused if it fits": it does not fit (it is time-based); resets reuse the respawn-to-spawn path.
6. Section 4, material class: scan voxels carry none; scans give floor, ceiling or wall by surface normal, 'obstacle' only for track objects and lesson worlds.
7. Section 6, "the start page is plain HTML": two pages, the site's static `/{lang}/sound/` and the simulator's start screen built outside the `#ui` live region.
8. Done-means: Winter Garden ships 3.2 cm walls, 16 cm at x5; the test PC needs the 1.6 cm refine (8 cm at x5) first.
9. Section 8, "after both channels confirm": for mail that means Gmail SMTP accepted it; there is no read receipt.
