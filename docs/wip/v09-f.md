# v0.9 lane F: the owner's replies reach the pilot in the pilot's language

The owner's item 4 of message 22 ([v09-plan.md](v09-plan.md)). Branch `v09-f`. Only `apps/api` (Python, stdlib),
the bot/mail/admin dictionaries and the admin's mail-state list are touched; nothing in the simulator.

## 0. What was found (root causes)

1. A reply the owner writes in Telegram goes through `OwnerBot._message -> IdeasService.reply -> _mail ->
   Mailer.compose`. `compose` puts the owner's text **as he wrote it** between a greeting and a signature
   that exist only in en/es/pl/ru and are chosen from `record["lang"]`.
2. `record["lang"]` is the language of the **form** the pilot used (the site language), not the language the
   pilot **wrote in**. A Polish page with an English message gives a Polish frame around... whatever the owner typed.
3. The done summaries have the same shape: `set_done_summary` picks `summary[form language] or summary["en"] or
   first` and a plain-text summary typed in Telegram is stored under the *form* language key whatever its real
   language (often Russian). Only four keys exist, so an agent cannot write a German pilot's summary at all.
4. Nothing checks the language of what is sent. An e-mail can reach a Polish or German pilot in Russian.

## 1. Design

**`apps/api/translate.py`** (stdlib `urllib`): `GeminiConfig.from_env` (`GEMINI_API_KEY`, `GEMINI_MODEL` default
`gemini-2.5-flash`, `GEMINI_TIMEOUT_S`, `GEMINI_API_BASE` for the test endpoint: https only, plain http only to this
machine, as the SMTP test switch), `Gemini.call_json` (REST `models/<model>:generateContent`, the key in the
`x-goog-api-key` header so it is in no URL and no log, structured JSON output, temperature 0, thinking off for the
flash family, a timeout and **one** retry for transient failures only: timeout, network, HTTP 408/429/5xx; an HTTP 400
is asked again without the optional thinking switch, then without the response schema), and `Translator`:

- `detect(text)`: the language a pilot wrote in (ISO code + English name + confident flag, validated).
- `translate(text, target)`: `{source_language, translation}`; the prompt is strict (data, not instructions; only
  the translation; keep names, links, numbers, code, line breaks and the tone; add nothing). Checks on the answer:
  not empty, not absurdly long or short, every URL and e-mail address of the original is still there.
- `frame(code)`: the greeting/signature/footer strings for a language outside en/es/pl/ru, translated once with
  their `{placeholders}` checked, cached in `DATA_DIR/mail-frames/<code>.json`. No frame: English at worst.
- `plan(rec, text)`: the one decision, returned as a `Plan`: which language the e-mail is in, the body, the owner's
  original when the body is a translation, and whether the text may go at all.

**Pilot language.** A report's text is the pilot's own: Gemini detects it once and the answer is cached on the
idea record (`pilotLang {code, name, at}`); a text too short to tell, no key or a failed call falls back to the
form language, then English (not cached, so the next reply tries again). A note (the owner's `/note`) is the
owner's words about the pilot, so its language is the `#pl` tag or English.

**Decision (`Translator.plan`).** Target = pilot language (or English when its frame cannot be had).
1. Key set and Gemini answers: source language == target -> the owner's words go as written; else the
   translation goes, the original is kept in the mail (`orig`, `tr {from, to, toName, model}`).
2. No key or a failed call (never send what the pilot cannot read): `langguess.classify` (offline, function words
   and scripts of en/es/pl/ru) -> English, the pilot's language or ASCII text with no sign of another language goes
   as written; anything else **waits** (`waiting_language`) with the reason. A service that did not answer at all
   (timeout, network, 5xx) while the pilot's language was asked is not asked a second question in the same
   breath: the owner's webhook would wait twice as long (worst case about 25 s; about 50 s for a pilot in a
   language outside en/es/pl/ru whose frame build and translation both time out, under nginx's 60 s).

**Service.** `reply()` and `set_done_summary()` plan BEFORE the store transaction (a network call must not hold the
file lock); the undo window starts after the translation; `set_done_summary` decides again if another writer changed
the summary meanwhile (up to 3 times). A bug in the translator never loses the owner's words: the text then waits.
`use_original(mail)` rebuilds a still-queued translated e-mail around the owner's words with a new undo window.

**Telegram.** A translated reply shows "Translated (ru -> pl)" with the whole e-mail and the owner's original under
it, inside the 60 s undo window; buttons Cancel and "Send my original instead" (`o:<mail>`). A waiting text gets a
notice naming the pilot's language and why, with "Send as written" (the existing `w:` verb = `send_mail`) and Cancel;
replying again in English or the pilot's language is the other way out. Nothing waits silently.

**Done summaries.** The draft body is chosen by the pilot's language (the summary written in it, else English,
else the first; a summary filed under a language it is not written in is not trusted); written in another language it
is translated and the draft says so. A plain text typed in Telegram is stored under the language Gemini found in it.
Drafts that cannot be checked wait like replies. The agents' CLI shows `wrote=<code>` and which e-mails were
translated or held.

**Admin.** The reply route uses the same service, so it translates the same way; the admin's mail-state list
learns `waiting_language` (a state it does not know is dropped by the client's parser) with Send ("as written") and
Cancel, and a label in four languages.

**Not changed on purpose.** The quote of the pilot's own words stays as they wrote it; the A6 hash and the
simulator are untouched; mails already sent are not rewritten.

## 3. Traps met

- Agent tools decode a backslash-u sequence typed in a file or command before it reaches the disk, so a test string
  meant as an escape became a real Cyrillic or Polish letter in a source file (B18). Fix: a one-off script that
  writes the escape as `chr(92) + 'u' + hex`, and a check for non-ASCII in the new files before B18.
- Windows refuses a connection to a closed local port slowly (longer than a 0.5 s test timeout): the test for a
  dead endpoint accepts `network` or `timeout`.
- `FakeSMTP`/`FakeTelegram` shut down in up to 0.5 s each (serve_forever's poll); the fakes now poll every 20 ms,
  which cuts every World's tear-down.

## Review round 2 (an independent reviewer, six findings; each checked by running it)

All six were real. Fixed in one commit, each with a test that fails without the fix (negative controls below).

- [x] 1 (medium) a translation was never tested for its language, and the model's "this is already in your language"
      was believed: a Russian text echoed back reached a Polish pilot. Now `Translator._wrong_language` asks the
      offline net (`langguess`): the answer must not be surely in another language than asked, the claim must not be
      surely false. A refusal is `bad-translation` and the text falls to the offline rule (English goes, the rest waits).
      The net is sure only about en/es/pl/ru (and Cyrillic for any other language: German "was"/"in" read as English,
      Portuguese as Spanish, Czech as Polish), so for another language the test is "Cyrillic where Latin was asked" and
      "the answer is the original". An unchanged answer is no longer shown as "Translated".
- [x] 2 (medium) a held thank-you (`waiting_language`, kind `done`): the notice was linked as an e-mail, so the owner's
      reply to it sent an ordinary "Re:" e-mail and the held thank-you stayed. Now `OwnerBot._show_held` links a held
      thank-you's notice as a draft (a reply is a new summary, which supersedes the held e-mail), says "reply to this
      message" for it, and Done/Edit/stale-draft show the held thank-you instead of asking for a summary again.
- [x] 3 (low) "neither in English nor in English": `mail.languageEn`, `mail.languageDone`, `mail.languageDoneEn` in
      four languages (an English e-mail names no second language).
- [x] 4 (low) the admin: `THANKS_PENDING` has `waiting_language` (the card says "review", the dialog opens at the
      held e-mail instead of writing a second thank-you), and Edit is offered for it. Not done: the admin's reply path
      still parses no `tr`/`orig` (owner question 3 of the lane F summary).
- [x] 5 (low) `http.client.HTTPException` (IncompleteRead of a chunked answer, a connection closed before the status
      line) is a transient `network` failure: tried once more, like the rest. `FakeGemini` has a `short` step.
- [x] 6 (low) `ideas.DRONE_MARK` is the one home of the header's first words (`drone_header` and `translate.pilot_words`).
      The test builds its record with `record_from_report` and changes the mark to prove the follow. Not done: a way
      to correct a wrong cached `pilotLang` (the reviewer's "optionally").
- Tests: the fake Gemini's default "translation" (`[pl] text`) is in no language, so the new check refuses it; the
  tests that need a translation set a real one in `glossary`. API suite 296 OK (280 before, 16 new).
