# v0.9 lane C — scene settings: default scale, sharing carries settings, macro hint

Items 14, 15 and 17 (product part) of the owner's message 22 (`docs/wip/v09-plan.md`). Worktree `C:/dev/gsfpv-v09-c`,
branch `v09-c`, base `631fd5f`.

## What was there (root causes of the gaps)

- `CatalogScene.scale` existed (admin editor field, `scene-default` "save as default") but only 0.25..4, and the pilot's
  `[` `]` range is 0.25..100 (prefs `SCALE_MIN/MAX`). A macro scan needs x3..x30.
- The owner's default reached the simulator only through the prefs resolver built from the **picker's list**
  (`presetResolver(presets, showcase)` -> `curatedScale`). `GET /api/catalog` leaves out `hidden` scenes, and a scene
  opened by a pasted SuperSplat link or `/fly/?scene=<id>` that the picker does not list got no default at all.
- Sharing carried the scene id and (lane R) `budget`/`stochastic` only. Nothing of the sharer's scene settings.
- A prefs session layer exists (`?walls=`, `?drone=`, `?set.<id>=`) but it is **global for the page**: a scene-scoped
  value there (scale) would follow the pilot into the next scene on N. A shared link is about ONE scene.

## Design

### 14. Default scale per scene

- Range 0.25..100 everywhere: `packages/scenes catalog.ts` (`CATALOG_SCALE_MIN/MAX`, `readScene`), `apps/api/admin.py`
  (`clean_scene`), the admin editor field, `app/scene-default.ts`. One shared fixture
  (`packages/scenes/test/fixtures/scene-scale-range.json`) is read by the TypeScript and the Python test, so the two
  writers cannot drift (the fly-deep-links.json pattern).
- History: the field lives in the catalogue entry, so publish / history / restore / `catalogDiff` already cover it.
- **Public API.** `GET /api/catalog` (public, ETag, `max-age=60`) gets one more top-level key, `defaults`:
  `{ "<sceneId>": { "scale": 3 } }` for every scene of the **published** catalogue that is **hidden** and has a scale
  other than 1. A hidden scene is one the owner keeps in the admin but not in the picker (maybe a scan he only links
  to); the picker's `scenes` array still leaves it out, so `defaults` is how its size reaches the simulator. Only the
  scale is exposed: no title, no other field. The published scenes keep carrying `scale` in `scenes[]`. Old clients ignore
  `defaults`; a new client without it (the static showcase fallback, an old API) just has no extra scenes.
  The **unpublished draft is not exposed**: pilots see the published list for every field (`admin.status.dirty`), the scale
  is no exception; Publish is the one switch. (Owner question: should a draft-only scene count? See the report.)
- **Client.** `SceneCatalog.defaults` (strictly parsed by `readCatalog`); `sceneDefaultScale(catalog, id)` is the one
  lookup (scene entry, else `defaults`). `boot.ts` hands `catalog.defaults` to `openPagePrefs`, which feeds the prefs
  resolver's `curatedScale`. Every path that opens a scene reads `prefs.get('scene.transform', {scene})`, and the store
  returns the resolver's scale as the default: the picker, `/fly/?scene=<id>`, a pasted link, N / Shift+N / F /
  auto-switch (`SceneHost.load`) - no per-path code.
- **Precedence** (pure `resolveSceneScale`, tested): a shared link's `size` > the pilot's own saved scale for the scene
  (`scene.transform` stored) > the owner's default > 1. The store already gives "stored > default"; the shared link is
  the visit layer below.
- Admin editor: the `scale` number field accepts 0.25..100 (label says "Default scene size", help: applies on the site and
  on a SuperSplat link, also for hidden scenes after Publish).

### 15. Sharing carries the scene settings

- **Visit layer in the prefs store** (`PrefsStore.setVisit/clearVisit/visitOf/keepVisit`): values for ONE scene, this
  visit only, never stored. Read order: session (URL/test) > visit(scene) > stored > default. A pilot's own write of the
  same setting (`source: 'user'`) removes its visit entry (the pilot's choice wins from then on, like `forgetLink`).
  Changes emit `PrefChange` with `source: 'session'`, so the features that follow the store (scale, walls, floaters,
  ceiling, wind) apply a Reset live, as they do for `?set.`.
- **Pure module** `packages/scenes/src/shared-settings.ts`: `SharedSettings`, `parseSharedSettings(URLSearchParams)`
  (strict: ranges, unknown ignored, whole parameter dropped when out of range), `sharedQuery()` (canonical order, the
  string appended to the fly link), `diffShared(flown, defaults)` (only what differs from the scene's defaults),
  `describeShared()` (data for the chip), `sharedToPrefs()` (setting ids and values), `SHARED_PARAMS`.
  Parameters (compact): `sz` scene size, `wl` walls (`0`/`1`), `fl` floater filter (blocks), `wd` wind (`off` or
  `from,speed,gust`), `ce` collision ceiling (`off` or metres in scan coordinates), `dr` drone preset (reuses the
  existing `?drone=` of the prefs session layer, so it is parsed there too). Render mode/budget travel as the existing
  `budget` / `stochastic` of the scene link (lane R's parser); `flightDrawing` now also folds in the sharer's
  `display.drawing` (stochastic / sorted) so a mode picked in Settings is shared, not only a link's.
- **Sender.** `share/shared.ts` reads the sharer's effective settings for a scene from the store (the same code for a
  flight and a picker card), diffs them against the scene's defaults, and the share request carries `shared`.
  `shareLink` uses the fly deep link + `sharedQuery` instead of the scene page when `shared` is not empty (the static scene
  page cannot carry them); `POST /api/share` takes `shared`, validates it with the Python mirror (`shared_settings`),
  stores it in `share/<id>.json`, and `GET /s/<id>` appends it to the fly link (`fly_link`). Fixture
  `fly-deep-links.json` gets rows with `shared`, read by both writers.
- **Receiver.** `boot.ts` parses the page's query once; with a `?scene=` page it opens the visit layer for that scene
  before `fly()`. A new feature `builtin/shared-settings.ts` shows the chip "Shared settings: x3, walls off - Keep /
  Reset" (4 languages) while the layer is on. Keep writes each item as the pilot's own (the same `set` as setting it by
  hand), Reset clears the layer (live) and the session-layer drone, both strip the parameters from the address. A scene
  switch ends the visit of the scene left (layer cleared, parameters stripped from the URL so a reload of the next scene
  is clean). The saved prefs are never touched until Keep.
- Out of scope / honest limits: the live wind of the place (`wind.mode = now`) is weather, not carried. Render budget /
  stochastic are the scene link's own request (lane R), shown by lane R's HUD line, not part of Keep / Reset.

### 17. Macro hint and landing text

- `macroHint` (pure, tested): shown once per browser when a scene starts at the **owner's** default scale >= 2 with no own
  saved scale of the pilot; the HUD line says it is a small real object scaled up to fly like a big building and that
  `[` / `]` change the size. Displayed when the flight actually runs (after the Controls screen), remembered in
  `localStorage` (try/catch; a blocked storage shows it again, harmless).
- Landing "Scene scale" block: a macro paragraph (fly among plants, around a fly, as if it were a giant building) and the
  reverse (shrink a city to a model, fly it with a micro drone), 4 languages, only what the product does.
