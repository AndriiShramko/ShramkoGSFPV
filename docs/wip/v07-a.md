# v0.7 lane A: catalogue, scene pages, SuperSplat facts, wind of the place

The owner's items 4 and 5 of message 18 ([v07-plan.md](v07-plan.md)), the admin editor of the v0.7
catalogue fields and `GET /api/wind/<id>`. Branch `v07-a`. This note says what changes, why, and where
each piece lives, so an agent can find it from the module layout.

## 1. Item 4: every published scene is in the picker

**Root cause.** The picker's filter (`packages/scenes/src/library.ts`, `SceneFilter`) is one object for
every tab, persisted per browser, with `collisionOnly: true` by default. The v0.6 picker rows
applied it to the owner's catalogue, so a scene he published without a SuperSplat collision file
(70b50d42 Wroclaw Cathedral, 0230d903 Muster Truck Show) never showed.

**Structural fix.** Which filters a tab obeys becomes data: `TAB_FILTERS` in `library.ts` says, per
tab, which of the filter's keys apply. The catalogue tab is the owner's shop window: it obeys none
of the walls filter (every published scene, a "no walls" badge on the card), kind and flown stay (they
default to "all" and the pilot sets them by hand). Favourites are the pilot's own picks: a starred
scene stays, badge and all (review fix: the first cut filtered them, so a starred no-walls scene
vanished). Recent and the SuperSplat tab (discovery) keep the walls filter. `pickerList` takes a tab's
cards (`tabCandidates`), applies the controls the table names (`filterCandidates`, the one place the
filter rules live) and counts what the filter hid, so an empty tab says "no scans match the filter"
when that is the reason (`pickerEmpty`), not "scans you open appear here". The picker hides a control
the open tab does not obey, so the screen never shows a filter that does nothing. Tests: both scenes
of the owner appear with the default filter, a starred one stays in Favourites; the negative control
applies every control to every tab (the v0.6 rule) through `filterCandidates` and must lose them.

**Admin: draft vs live impossible to miss.** `catalogDiff(draft, live)` (pure, `catalog.ts`) lists the
scenes added, changed (which fields), removed and moved since the last publish. The admin's sticky bar
shows "N changes not published" with the Publish button highlighted only then; every changed row has
a badge (new, changed, moved), removed scenes are listed under the bar; the browser warns before
leaving with unpublished changes.

## 2. The landing shows the published catalogue

- `src/generated/catalog.json` is a committed snapshot of the published catalogue: a build depends on
  the commit alone (review fix: the first cut fetched the live `/api/catalog` in every prebuild, so CI
  and two builds of one commit could differ). `pnpm --filter @gsfpv/site catalog:refresh`
  (`scripts/catalog-snapshot.mjs --refresh`: 4 s, validated, a bad answer keeps the file) refreshes it,
  then a commit; the prebuild only reports what the file holds.
- `CatalogGrid` (client component) renders the snapshot on the server (crawlers and JS-off visitors
  see every card) and refreshes from `/api/catalog` in the browser. Each card links to its scene page
  `/{lang}/scenes/<id>/` and to the simulator.
- The "Places" block links to `/{lang}/scenes/`. `sitemap.ts` lists `/{lang}/scenes/`.

## 3. Item 5: facts from SuperSplat when a scene is added

**Research (2026-10-13, one scene, 0230d903 and 70b50d42).** PlayCanvas has no public single-scene GET
(`/api/splats/<id>` answers 404; its client only PUTs there). superspl.at's scene page is a React
Router app; its loader data is served at `https://superspl.at/scene/<id>.data` as a turbo-stream
(a flat JSON array of values with index references; dates as `["D", ms]`). It carries `splat {title,
description, version, thumbnails, format, size, downloads {enabled, license}, createdAt, voxelTask,
softwareTools}` and `user {username, fullName}`. There is no tag field: tags are the description's
hashtags plus the software tools named. "Walkable" has no flag either: the server asks the CDN for
`<id>/v<version>/scene.voxel.json` (HEAD).

- `apps/api/turbostream.py`: the decoder (pure, tested on a recorded answer).
- `apps/api/superspl_facts.py`: `GET /api/admin/superspl/<id>` (admin session only): the facts
  (title, author = full name or user name, `origin.user`, licence "CC BY 4.0" from the code, our
  `origin.description` (600) / `origin.created` / `origin.tags`, thumbnail, version, walkable, format,
  sizeMb), cached 10 min in RAM, at most 20 upstream calls a minute, no redirect, nothing of the
  admin's request goes on. The admin's "Add a scene" fills the entry from it; "Refresh from
  SuperSplat" on a scene re-reads it and shows what would change before it is applied.
- A pasted link's `?budget=8&stochastic` goes to the entry's `render` (`linkRender` in
  `packages/scenes/src/catalog.ts`; lane R keeps the same parameters in `parseSceneInput`).

## 4. Item 5: scene pages for search and answer engines

`/{lang}/scenes/` and `/{lang}/scenes/<id>/` for every published, not hidden scene, rendered by the
API (`apps/api/scenepages.py`) into templates the site build makes:

- **Templates.** `apps/site/src/app/scene-template/[locale]/{scene,index}/page.tsx` use the landing's
  own components (header, footer, sections, classes). `scripts/scene-templates.mjs` (postbuild) takes
  their HTML, drops every executable script and preload (the pages run no JavaScript), checks every
  slot is there, and writes `out/scene-templates/<kind>.<lang>.html` plus the phrase dictionaries and
  `share.json`. The route folder itself is removed from `out/`. nginx answers 404 for
  `/scene-templates/`; the API reads them from the live release (compose mounts `releases/` read-only
  into `gsfpv-api`), so a new design ships with the release.
- **Slots.** A double-brace name is escaped text (`&<>"'` escaped), a triple-brace name is raw and
  reserved for the JSON-LD the API serialises itself (`<` `>` `&` U+2028 U+2029 escaped as `\uXXXX`).
  `[[#list]]...[[/list]]` repeats, `[[?name]]...[[/name]]` shows when set. Unknown names are an error
  at load time, not an empty string at run time.
- **Text policy.** Our title wording (per language); a facts paragraph generated from the entry's data
  in each language (kind, place, walls and voxel size, scale ideas, wind, drone, size); the entry's
  `about` when present; SuperSplat's description only as a quote of at most 200 characters (links
  removed) credited to the author; tags as keywords. The phrases live in
  `packages/i18n/locales/scenepage/<lang>.json` (checked by `i18n:check`).
- **Head and data.** Canonical, hreflang (4 + x-default), Open Graph and Twitter with the poster,
  JSON-LD: WebPage + BreadcrumbList + CreativeWork (author, licence URL, `isBasedOn` origin URL,
  keywords, `contentLocation` Place with GeoCoordinates when known) + FAQPage. "Fly this scene" deep
  link (`render` parameters included), share links (no script), credit and licence line to SuperSplat.
- **Security.** Every value is escaped; ids, URLs and numbers are re-validated by the API; the page's
  CSP is `script-src 'none'`; hostile titles are the negative controls of the tests.
- `GET /scenes/sitemap.xml` (lastmod = the catalogue's publish time) is named in `robots.txt`;
  `GET /scenes/llms.txt` lists every scene page with a one-line summary and is linked from `llms.txt`.

## 5. Admin editor of the v0.7 fields

Per scene: geo (lat, lon, place; "Find place" by name through `GET /api/admin/geo/search?q=`, Open-Meteo
geocoding), compass heading, wind (from, speed, gust; "Prevailing wind of this place" through
`GET /api/admin/wind/climate?lat=&lon=`: five full years of hourly 10 m wind from Open-Meteo's archive,
speed-weighted vector mean direction, median speed, median gust above the mean; cached in
`DATA_DIR/wind-climate/`), collision ceiling, render (budget, stochastic), about in 4 languages.
Admin routes are added through a small route table on `AdminApi` instead of a longer if-chain.

## 6. Public wind of a scene

`GET /api/wind/<id>?mode=now` (`apps/api/wind.py`): `{"ok": true, "fromDeg", "speed", "gust", "at",
"source": "now"}` from Open-Meteo's forecast `current` at the scene's geo, cached 15 min per scene, 404
for an unknown, hidden or geo-less scene, 30 requests a minute per visitor and a global upstream bucket.
`gust` is the gust above the mean (`wind_gusts_10m - wind_speed_10m`, at least 0), as in the contract's
`SceneWind`.
